# 인터뷰 가이드 — 질문의 큰 틀

진행 순서: **왜(목표) → 무엇이 있나(현장·데이터) → 누가(사용자) → 무엇을(기능·화면) → 어떻게(비기능·연동) → 언제(우선순위)**
데이터 소스(Phase 3)를 기능보다 먼저 묻는다. 모니터링 시스템은 "어떤 데이터가 실제로 들어오느냐"가 기능의 한계를 정하기 때문.

## Phase 0. 배경·목표·범위
- 이 시스템을 왜 만드나? 지금 현장은 무엇으로 현황을 보고 있고, 무엇이 불편한가?
- 성공하면 무엇이 달라지나? (측정 가능한 지표: 정지 대응시간 ○분 단축 등)
- 누가 발주/의사결정자인가? 납품 형태(사내/고객사/제품화)?
- 범위: 대상 공장·라인 수, 포함/제외(MES 기능, 제어, 품질 등)
- 프로토타입(`front`, 3D 뷰)은 어디까지 합의된 것인가, 시안일 뿐인가?
- (부트캠프) 팀 구성·기간·발표일·평가 기준, **발표 데모 시나리오**: 데모 흐름이 기능 우선순위를 정한다
- **완료조건**: 목적 1문장, 성공지표 1개 이상, In/Out 범위 목록

## Phase 1. 현장·도메인 구조
- 계층 구조: 공장 → 라인 → 공정 → 설비(로봇/지그/컨베이어) → 센서? 각 단계 개수
- 차체 공장 공정 A~F의 실제 이름과 순서, 흐름(직렬/병렬/버퍼)
- 생산 방식: 혼류 생산 여부, 차종/사양, 택트타임(C/T), 교대·근무 캘린더
- 설비 상태 정의: 가동/대기/정지/고장/계획정지… 누가 어떻게 판정하나?
- 현장 용어·약어 (→ 용어집)
- **완료조건**: 계층·개수 확정, 상태값 목록과 판정 기준, 용어 20개 내외

## Phase 2. 사용자·역할·사용환경
- 사용자 유형(작업자/반장/설비보전/생산관리/공장장)별 보는 것과 하는 행동
- 각 사용자의 "하루 중 이 화면을 여는 순간" 시나리오
- 권한: 조회/조치입력/설정 변경, 로그인 방식(SSO/AD/자체)
- 사용 장소·기기: 현장 대형 상황판(TV), 사무실 PC, 태블릿/모바일? 해상도
- **완료조건**: 역할-권한 매트릭스, 역할별 핵심 시나리오 1개씩

## Phase 3. 데이터 소스·수집
- 데이터 출처: PLC(제조사/모델), OPC-UA, MES/DB, 센서 게이트웨이, 수기 입력?
- 수집 항목(태그): 상태, 생산수량, 사이클타임, 알람코드, 진동/전류/온도 등
- 수집 주기·지연 허용치, 데이터 품질 문제(누락·시간불일치) 처리
- 이미 수집 인프라가 있나, 새로 만드나? 우리가 붙는 지점은?
- 보존 기간, 이력 데이터 양
- **완료조건**: 소스별 연동 방식, 태그 목록 초안, 수집 주기, 우리 시스템 경계

## Phase 4. 기능 상세 (기능 단위로 반복)
대상 후보: 실시간 모니터링 / 공정 상세 / 가동률(OEE) / 예지보전 / 알람·알림 / 이력·리포트 / 3D 뷰 / 기준정보·설정
각 기능마다 같은 질문 세트:
- 목적과 사용자, 입력(트리거) → 처리 규칙 → 출력
- 계산 산식 (예: 가동률 = ?, 계획정지 제외 여부, 집계 단위 시간/교대/일)
- 예외: 데이터 끊김, 설비 교체, 교대 경계, 자정 넘김
- 알람: 등급, 조건, 확인(Ack)·조치 입력, 알림 채널(화면/소리/문자/메신저)
- 예지보전: 기준이 임계값인가 모델인가, 누가 정의, 결과로 무엇을 하나
- **완료조건**: 기능별 규칙·산식·예외 확정, FN ID 부여

## Phase 5. 화면 상세 (화면 단위로 반복)
- 화면 목록과 이동 흐름(메뉴 구조)
- 화면별: 표시 항목, 갱신 주기, 필터(공정/기간/차종), 클릭 시 동작, 색상·상태 표현 규칙
- 빈 상태/오류/수신끊김 시 표시
- 프로토타입 화면을 같이 보며 "유지/변경/삭제" 확인
- **완료조건**: SCR 목록, 화면별 항목표와 이벤트표

## Phase 6. 비기능 요구사항
- 실시간성(화면 반영 지연 ○초 이내), 동시 사용자 수, 상황판 24시간 구동
- 가용성(장애 시 허용 중단시간), 백업·복구
- 보안: 망 분리, 외부 접속, 감사 로그
- 배포: 온프레미스/클라우드, 서버 사양 제약, 브라우저 종류
- **완료조건**: 수치로 된 NFR 목록

## Phase 7. 아키텍처·API·연동
- 백엔드 기술 제약(사내 표준 언어/DB/메시지큐)?
- 실시간 전송 방식(WebSocket/SSE/폴링) 선호·제약
- 외부 연동: MES, ERP, 그룹웨어 알림, 기존 DB
- 인증 방식, API 버전 정책
- **완료조건**: 구성도 초안, API 목록(엔드포인트·방식), 연동 대상 목록

## Phase 8. 우선순위·일정
- 기능별 MoSCoW(Must/Should/Could/Won't)
- MVP 범위, 오픈 목표일, 단계별 릴리스
- 검수(인수) 기준: 누가 무엇을 확인하면 완료인가
- **완료조건**: 우선순위가 붙은 FN 목록, 마일스톤

## 질문 기법 메모
- 열린 질문으로 시작 → 보기 있는 질문으로 좁힘 → 수치로 확정
- "보통은요? 가장 최악의 경우는요? 마지막으로 그게 일어난 건 언제였나요?"
- 사용자가 해결책을 말하면 그 뒤의 문제를 묻는다 ("그게 있으면 무엇이 해결되나요?")
- 회차 끝: "제가 이해한 것" 요약 → 맞는지 확인
