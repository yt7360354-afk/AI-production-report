## 1. 데이터 흐름

```
 수집                     전달                 백엔드                         화면
[iG5A 인버터] ─Modbus─┐                      ┌─ ① 원천 저장 (시계열·사이클)
                       ├─ Node-RED ─ MQTT ──▶├─ ② 상태 판정 (FN-002) → 상태 이력·알람
[시뮬레이터] ─OPC UA──┘                      ├─ ③ 현재 상태 (메모리)  ──── 1초 push ───▶ 대시보드·공정상세·3D
                                              ├─ ④ 집계 (OEE·생산·재공) ── 조회 ────────▶ 가동률·리포트
                                              ├─ ⑤ 알림 발송 ──────────── 이메일·슬랙, 화면 토스트
[사용자 입력] ◀──────── 조회·저장 ───────────▶└─ ⑥ 기준정보·설정 (목표, 관리값 기준, 계정)
```

- **상태(RSID) 판정은 백엔드가 한다.** 앞뒤 공정 상태와 재공을 함께 봐야 해서 설비 쪽에서는 판정할 수 없다. 설비·시뮬레이터는 원천 신호(운전/정지/트립/안전)만 보낸다.
- 제품 ID는 슬리팅 투입 때 발급되고, 이후 모든 사이클·검사 기록에 붙는다 (D-86). 화면의 물류 점은 이 기록에서 만든 "제품 이동" 이벤트다 (D-81).
- 계획정지 일정은 시뮬레이터 시나리오가 만들어 백엔드 기준정보(근무 캘린더)에 넣고, 그 시간에 설비를 멈춘다. 화면 입력은 없다 (D-74).

## 4. 수집 데이터 — 무엇을, 얼마나 자주

### 4.1 주기 기준
- 24시간 가동 = **86,400초/일** (D-42). 계획정지 중에도 시계열은 수집.
- 공장 택트 **20초 [가정]** → 하루 약 4,320개. 라인 6개가 나눠 만들므로 **라인 CT = 120초** [가정].
- 라인 안은 직렬이라 슬리팅·프레스 1~4단·용접 모두 표준CT 120초 (D-80). 도장 2대는 6개 라인 물량을 나눠 받아 40초. 비전 1대는 공장 물량 전부를 받아 20초(= 공장 택트, D-90).
- 공정 검사는 사이클 끝에 붙는 판정이라 따로 시간이 들지 않는다고 본다 [가정 A-09].

| 공정 | 설비 | 표준CT [가정] | 1대 하루 사이클 | 시계열 주기 |
|---|---|---|---|---|
| A 코일입고 | - | - | 입고 이벤트 하루 수십 건 | - |
| B 슬리팅 | 6 (라인당 1) | 120초 | 720 | **1초** (인버터 폴링) |
| C 프레스 | 24 (라인당 4단) | 120초 | 720 | 사이클마다 (데이터셋이 사이클 단위) |
| D 용접 | 6 (라인당 1) | 120초 | 720 | 사이클마다 |
| E 도장 | 2 | 40초 | 2,160 | **5초** (데이터셋 간격) |
| F 출고(비전) | 1 | 20초 | 4,320 | 검사마다 |

- 불량 제외(기본 0.5% × 4공정 [가정 A-10])만큼 뒤 공정 수량이 조금씩 줄어든다.

### 4.2 메시지 내용
| 메시지 | 보내는 곳 | 시점 | 필드 |
|---|---|---|---|
| telemetry (시계열) | 슬리터, 도장 | 1초 / 5초 | 설비 ID, 시각, 관리값들 |
| cycle (사이클) | 슬리터(환산), 프레스, 용접, 도장 | 제품 1개 끝날 때 | 설비 ID, **제품 ID**, 시작·종료 시각, 실제 CT(ms), 그 사이클의 관리값. 슬리팅 사이클 시작 = 제품 ID 발급 |
| inspection (검사) | 공정 B~E 검사(시뮬레이터), 비전검사기 | 공정 끝 · 검사마다 | 공정, 설비 ID, 시각, 제품 ID, 판정(양품/불량), 불량 사유 |
| signal (원천 상태) | 모든 설비 | 바뀔 때 + 10초마다 재전송 [가정] | 설비 ID, 시각, 운전 여부, 트립 여부·코드, 안전 신호 |
| receipt (입고) | 코일입고 | 입고마다 | 시각, 수량 |

- 프레스·용접 사이클의 관리값은 데이터셋 행을 차례로 재생해 채운다. 1대분 데이터에 설비마다 노이즈·오프셋을 준다.
- 실설비 슬리터 라인은 인버터가 수량을 주지 않으므로, 백엔드가 운전시간 × 속도 환산으로 사이클을 만들 때 제품 ID를 발급하고 시뮬레이터가 그 제품을 프레스부터 이어받는다 [가정].
- 공정 검사 판정: 사이클 관리값이 기준 이탈이면 불량, 아니면 공정별 기본 불량률 0.5%로 무작위 [가정 A-10].
- 비전 판정은 데이터셋 라벨(불량 약 21%)을 그대로 쓰면 불량률이 너무 높다 → 재생 시 불량 비율을 조정 [가정, 예: 2~3%].

### 4.3 MQTT 토픽 [제안]
```
sfaas/{라인}/{공정}/{설비}/telemetry
sfaas/{라인}/{공정}/{설비}/cycle
sfaas/{라인}/{공정}/{설비}/inspection
sfaas/{라인}/{공정}/{설비}/signal
sfaas/CM/A/receipt
```
- {라인} = L1~L6, PT(도장 라인), CM(입고·출고 공용)

예) `sfaas/L3/C/L3-PRS-2/cycle` → `{"ts":"2026-11-16T10:42:01.250+09:00","pid":"L3-20261116-0412","ct_ms":120400,"p1":276.0,"p2":274.5,"p5":550.5,"press_ms":550.2}`

## 5. 양 추정 (하루, 공장 전체)

| 데이터 | 계산 | 건/일 | 건당 크기 | 용량/일 |
|---|---|---|---|---|
| 슬리터 시계열 | 6대 × 86,400 | 518,400 | 약 80B | 약 41MB |
| 도장 시계열 | 2대 × 17,280 | 34,560 | 약 70B | 약 2.4MB |
| 사이클 (B·C 4단·D·E) | 4,320 × 7 | 30,240 | 약 110B | 약 3.3MB |
| 검사 결과 (B·C·D·E·F) | 4,320 × 5 | 21,600 | 약 70B | 약 1.5MB |
| 제품 | 4,320 | 4,320 | 약 80B | 약 0.3MB |
| 상태 이력 (비가동) | 39대 × 약 25회 [가정] | 약 1,000 | 약 160B | 작음 |
| 알람·알림 발송 | | 수십 | | 작음 |
| 미세정지 | | 수백 | | 작음 |
| 일 집계 | 설비 39 + 공정 + 라인 7 + 공장 1, 시간대별 (라인 7 + 공정 6) × 24 | 약 400 | | 작음 |
| **합계** | | **약 61만 건** | | **약 49MB (인덱스 포함 약 100MB)** |

- 1년(365일) 약 36GB. 그중 대부분이 슬리터 1초 시계열 → **원천 시계열 90일 보존** [가정]하면 시계열은 약 8GB에서 유지된다.
- 제품·검사 기록은 90일 보존 (D-86) → 약 0.2GB에서 유지. 사이클·이벤트·집계는 1년에 약 1.5GB씩 늘어난다.
- 들어오는 메시지: 초당 약 9건 (슬리터 6 + 도장 0.4 + 사이클·검사 약 0.6 + 상태 신호). MQTT·Node-RED·PostgreSQL에 부담 없는 양.
- 화면으로 내보내는 양: 1초마다 설비 39대 현재 상태 약 5KB + 라인·공정 요약 약 1KB + 제품 이동 이벤트 초당 약 0.4건 → 화면 1개당 약 6KB/초.

**API는 크게 두 갈래로 나뉜다.**
1. **실시간 push 1개 채널**: 현재 상태 스냅샷(1초), 제품 이동 이벤트, 알람 발생·해제 이벤트. 대시보드·라인상세·공정상세·3D·헤더가 함께 구독한다.
2. **조회·저장 REST**: 나머지 전부. 기간 조회는 날짜 단위가 기본이다.

## 9. 확인이 필요한 것 (API 명세 전에 정하면 좋은 것)
| # | 질문 | 제안 |
|---|---|---|
| 1 | 라인 택트·설비별 표준CT | 공장 택트 20초, 라인 CT 120초, 도장 40초, 비전 20초 (4.1). 제품 단위는 D-86으로 확정 |
| 2 | 원천 시계열 보존 기간 | 90일, 나머지 영구 |
| 3 | 화면 실시간 전송 방식 | 서버 → 화면 한 방향이라 SSE로 충분. 백엔드 기술이 정해지면 WebSocket도 가능 |
| 4 | 비전 불량률 | 데이터셋 21% 대신 2~3%로 조정해 재생 |
| 5 | 슬리터 관리값 기준(전류·토크) | 실제 모터 정격을 보고 정함 |
| 6 | 시뮬레이터 재생 속도 | 실제 시간과 같은 1배속 (빨리감기는 확장) |
