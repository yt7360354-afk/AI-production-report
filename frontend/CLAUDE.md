# 라인가동현황 모니터링 시스템 — 프론트엔드

Vue 3 + Vite + TypeScript. 공장 설비 39대의 상태를 1초마다 보여 주는 관제 대시보드.
요구사항은 `specs/`(PRD_노션 · 기능명세서 · 화면정의서 · 데이터정의서), 결정 근거는 `인터뷰/02_결정사항_미결.md`(D-xx), 배치 초안은 `wireframes/화면구성.html`.
명세와 코드가 다르면 명세가 기준이다. 현재 `src/`는 옛 프로토타입이다 (화면정의서 2-1절).

## 디자인 스킬 역할

| 스킬 | 맡는 일 | 쓰지 않는 일 |
|---|---|---|
| **unslop** (`/unslop`) | 처음 디자인 방향 잡기, 색·글꼴·간격 체계 정하기, 화면을 크게 다시 디자인 | 작은 수정·점검 |
| **impeccable** (`/impeccable …`) | 정해진 체계 위에서 다듬기와 점검: `polish` `audit` `critique` `harden` `adapt` `clarify` `layout` `typeset` `document` | 처음 방향 정하기, `overdrive` `bolder` `delight`, `live` 모드 |

- 순서: unslop으로 방향·토큰 확정 → `/impeccable document`로 `DESIGN.md` 생성 → 이후 화면 작업은 impeccable로 다듬고 점검.
- 한 화면에 두 스킬을 동시에 돌리지 않는다. 둘이 다르게 말하면 이 파일 → `DESIGN.md` → 스킬 규칙 순으로 따른다.
- taste-skill은 쓰지 않는다 (홍보 페이지용, 무작위 팔레트).

## 두 스킬 모두 지킬 것

**상태 색 (D-77)**
- R 가동 초록 · S 정지 회색 · I 대기 노랑 · D 고장 빨강. 예지보전 주의 = 노랑 테두리, 위험 = 빨강 테두리.
- 이 4색은 **의미 색(semantic)** 이지 강조색(accent)이 아니다. "강조색 1개" 규칙과 별개로 둔다.
- 색 이름만 정해져 있고 정확한 색값은 미정이다. 색값을 정할 때:
  - 중립 배경 위에서 글자·아이콘 대비 WCAG AA 이상. 노랑은 특히 확인.
  - 색만으로 구분하지 않는다. 상태 글자(R/S/I/D 또는 가동/정지/대기/고장)를 같이 표시 (색약 대비).
  - 예지보전 빨강 테두리가 고장(D) 빨강 칸과 헷갈리지 않게 구분.
  - 강조색은 상태 4색과 겹치지 않는 색조로.
- 상태 색 외의 색(배경·표면·테두리·글자·강조·차트)은 아직 정해진 것이 없다. unslop이 정한다.

**토큰**
- 모든 색·간격·글꼴·둥글기는 `src/style.css`의 `:root` CSS 변수로 한곳에 둔다. 컴포넌트는 변수만 쓰고 색값을 직접 적지 않는다.

**관제 화면 성격**
- 사무실 PC 1920×1080, 하루 종일 띄워 두는 화면. 배경·표면은 중립색, 강조색은 드물게.
- 그라데이션, 빛 번짐(glow), 반복 애니메이션, 카드 hover 확대, 장식용 이미지 없음.
- 1초 갱신: 숫자는 `font-variant-numeric: tabular-nums`, 값이 바뀌어도 레이아웃이 흔들리지 않게. 갱신마다 깜빡이는 효과 없음.
- 움직임은 의미 있는 곳만: 고장 발생 토스트, 배치도의 물류 점(D-81).
- 빈 값: 숫자 "-", 그래프·목록 "데이터 없음" (D-78).

**문구**
- 화면 문구는 한국어, 용어는 `인터뷰/03_용어집.md`를 따른다.
- 명세에 없는 기능·수치·문구를 지어내지 않는다. 데모용 값이 필요하면 그렇다고 밝힌다.

**코드**
- Vue 3 SFC + TypeScript. UI 라이브러리·차트 라이브러리를 새로 추가하려면 먼저 묻는다.
